# 简历速填 + 投递簿 · ResumeKit

一个可以直接加载到 Chrome / Edge 的本地插件，整合简历自动填写和投递记录管理。录入简历后，扫描并填写招聘表单，核对后点击“一键提交并记录”；插件根据网站结果保存投递记录。无需注册、服务器、付费服务或 API Key。

当前版本 **2.0.0 整合版**：保留多段经历、家庭成员和手动映射，新增岗位信息识别、核对后提交、提交结果记录、投递簿、状态筛选、跟进日期、CSV 导出与 JSON 备份。已通过本项目文件夹安装的用户，更新文件后到扩展管理页点击本插件的刷新按钮，再刷新资料页与招聘网页即可。已有简历资料保持兼容。

## 安装（约 1 分钟）

下载 [v2.0.0 整合版安装包](https://github.com/WSH-Z-12138/resume-autofill/raw/refs/heads/main/downloads/resumekit-v2.0.0.zip)，解压后按下面步骤加载。安装包只包含插件运行文件、演示与虚构示例资料。

1. 如果使用 ZIP 包，先解压，找到直接包含 `manifest.json` 的插件文件夹。不要选择 ZIP 文件，也不要选择它的上一层目录。
2. Chrome 地址栏输入 `chrome://extensions`；Edge 输入 `edge://extensions`。
3. 开启「开发者模式」，点击「加载已解压的扩展程序」，选择上述文件夹。
4. 在浏览器工具栏的扩展列表中，将「简历速填 + 投递簿 · ResumeKit」固定。首次安装会打开资料编辑页。

从 GitHub 下载 ZIP 后先解压；使用 Git 克隆项目时，直接选择克隆得到的项目根目录。选中的目录里应能直接看到 `manifest.json`。

Chrome 的加载流程参见 [Chrome 官方说明](https://developer.chrome.com/docs/extensions/get-started/tutorial/hello-world#load-unpacked)。不需要 Node.js、Python 或编译安装。

## 日常使用

1. 点击插件 →「编辑资料」，填写自己的信息，点击「保存资料」。左侧分类支持基本信息、求职意向、教育、工作／实习、项目、语言、证书／奖项、技能与自我介绍、家庭成员、自定义字段。
2. 打开招聘网页，展开要填写的表单。多段经历请先点击网页自己的「添加经历」，添加足够的空白行，并确保网页顺序与插件资料顺序相同。
3. 点击插件 →「扫描当前页面」。预览中能看到网页字段、对应的简历项目、准备填入的内容和跳过原因。
4. 核对勾选项 →「填入勾选项」。分步骤表单每进入下一步，都重新扫描。
5. 填完后检查网页、附件、验证码和协议，点击「识别岗位，准备提交」，核对公司、岗位、地点，按需填写简历版本。
6. 勾选“我已核对…确认提交此岗位申请”，点击「一键提交并记录」。也可以选择「由我在网页提交，开启自动记录」，然后自己点击网站最终提交按钮。
7. 点击「我的投递簿」查看结果、修改状态、设置跟进日期或导出备份。

## 提交后自动记录

- 岗位信息优先读取网页的 JobPosting 结构化数据，再尝试常见标题和公司元素；缺失或不正确时需自行修正，公司和岗位不能为空。
- 开启记录本身不会新增投递。检测到提交尝试后，先写入 **待确认** 记录，再点击网站按钮；仅在出现明确的新成功提示时改为 **已投递**，并记录提交及确认时间。失败提示会记为 **提交失败**。
- 没有结果提示、旧的成功提示、成功失败提示冲突、跨站跳转时，记录保留为待确认。请在网站核实后到投递簿手动改状态。
- 一键提交仅支持当前顶层文档里唯一、可见、可用且文字明确的最终提交按钮（如“提交申请”“立即投递”“Submit application”）。多个按钮、复杂组件或嵌入式表单需在网页手动处理；未识别到按钮时可手动添加投递记录。
- 原生表单校验未通过时不点击提交。插件不会替你处理验证码、上传附件或勾选网站协议，也不会自动遍历岗位或批量投递。
- 记录在本页开启后有效 30 分钟。关闭插件弹窗不影响记录；同源刷新、保留岗位网址的跳转及常见 success／confirmation／thank-you 等结果页会重新附加检测。进入其他岗位或未识别的跳转页时不会套用旧会话结果。跨站跳转、关闭标签页、浏览器重启后需手动确认结果，必要时重新开启记录。
- 同一岗位网址、公司、岗位组合会复用待确认／失败／待投递记录，避免重复新增。已有投递或后续状态的岗位会阻止再次一键提交。新岗位需重新识别和开启记录。

## 一个插件里的投递簿

通过插件弹窗或资料编辑页的「我的投递簿」打开。支持公司、岗位、来源、地点、薪资、联系人、简历版本、优先级、投递日期、跟进日期、下一步及备注。状态包括待投递、待确认、已投递、沟通中、面试中、已录用、未通过、已放弃、提交失败。

可搜索公司／岗位／备注、筛选状态、查看到期跟进及按日期排序。CSV 导出当前筛选结果；JSON 备份全部记录，导入时按岗位去重并新增，不覆盖原有记录。删除仅作用于你选择的一条记录。

整合版沿用原「投递簿」网站的业务字段，接受其 JSON 记录数组或 `{ "applications": [...] }`，不导入账号标识、密码、简历全文等多余字段。它是可独立运行的本地扩展版本，**未连接网页版账号，也不跨设备自动同步**。原网页版源码仍在 [toudibu-job-tracker](https://github.com/WSH-Z-12138/toudibu-job-tracker)。

默认保护已有内容；确实要替换时，勾选「允许覆盖网页已有内容」，再重新扫描。身份证号默认不勾选，「全选」也不会自动勾选证件字段。

「撤销本页填写」恢复本次页面打开期间的插件填写内容；你填完后自行修改过的字段会保留。网页刷新、跳转或关闭后，旧的撤销记录无法恢复。招聘网站如即时保存表单，撤销也可能触发该网站的保存行为。

## 没有识别的字段怎么填

点击插件 →「手动指定字段」，网页右下角会出现面板：

1. 在面板中选择一项简历资料。
2. 点击「① 点击网页选择输入框」，再点击网页中对应的输入框。
3. 核对内容，点击「② 填入并保存」。默认记住当前网站、当前路径、当前字段的对应关系，之后扫描会自动使用。

下拉选项与资料不一致时不会猜测。复杂下拉框、日期弹层可以先点击「复制内容」，再手动粘贴或选择。如果浏览器限制剪贴板访问，面板会选中内容，此时按 Ctrl+C 即可。

没有预设的个人信息，可以到「自定义字段」添加「字段名称」「填写内容」和「网页别名」。例如字段名「每周可实习天数」、别名「每周出勤天数,可实习天数」。别名用逗号分隔。

## 多段经历与日期

- 多段经历按照网页出现顺序填写。无法确定的字段会留空，或者通过手动模式指定到某一段资料。
- 调整、删除经历后，点击保存会清除该分类的旧网页对应关系，避免经历序号变化后填错。
- 年月资料不会擅自补出具体日期。网页要求完整日期、资料只有年月时，会提示手动处理。
- 「至今」可以填入普通文本框；网页使用原生日期控件时，需要你自己勾选网页中的「仍在职／至今」。
- 网页的新增经历、打开弹层和下一步按钮都由你操作；填写仅针对当前已显示的字段。最终提交需在插件核对后操作或在网页手动点击。

## 家庭成员

在左侧「家庭成员」点击「添加家庭成员」，可分别添加父亲、母亲、配偶、子女、兄弟姐妹等。每位成员支持：

- 与本人关系、姓名、性别、出生日期、年龄。
- 政治面貌、学历、职业／就业情况、工作单位、职务。
- 工作单位及职务（组合内容）、联系电话、电子邮箱、联系地址、备注。

「工作单位及职务」留空时，填表会自动组合已填写的工作单位和职务；也可以自己填写「已退休」等完整表述。年龄独立保存，请按实际情况更新，不会由年龄倒推出生日。

网页中应先添加足够的家庭成员行，并与插件中的顺序一致。通用版支持带「家庭成员／家庭情况／家庭信息／主要社会关系」等明确标题的普通表单和简单表格；表格需有对应列名，复杂的合并单元格或无法识别的字段可使用手动指定。

家庭区域会单独匹配，不会因为缺少家庭资料就借用本人的姓名、电话或工作单位。删除或调整成员顺序并保存后，该分类原来的手动对应关系会失效，需重新指定。家庭资料同样支持 JSON 导入导出。

## 先在测试页试用

资料页下方有「载入示例资料」。示例全部为虚构内容，载入后请先保存。它会替换当前编辑内容，建议先导出自己的资料。

直接用浏览器打开插件目录里的 `demo/index.html`，就能测试填表。若是本地文件页面，需要在扩展的「详情」中打开「允许访问文件网址」；安装或更新插件后，刷新测试页再使用。

`demo/submit.html` 提供成功、失败、结果不明、旧成功提示、多按钮、同站跳转及冲突提示的提交记录测试。投递记录需要 HTTP／HTTPS 页面，可在项目目录执行 `python -m http.server 8765 --bind 127.0.0.1`，打开 `http://127.0.0.1:8765/demo/submit.html`。测试页全部使用虚构数据，不发送真实申请。

测试页包含两段教育经历、工作和项目、两位家庭成员的表格、自定义字段、单选、下拉、日期、富文本、开放 Shadow DOM 和同源 iframe。检查按钮只在本地统计，不发送申请。

## 本地保存与备份

- 资料、对应关系和投递记录保存在 `chrome.storage.local`，不会同步到云端，也不会上传到本插件的服务器。短期记录会话保存在浏览器会话存储。本插件没有远程服务、统计代码或外部脚本。填入并提交网页后，招聘网站能读取所填内容。
- 投递记录只包含岗位信息、时间及结果依据，不保存简历全文、身份证或家庭资料。网址会清理凭据和跟踪参数，只保留常见岗位编号。
- 导出资料得到明文 JSON，包含当前编辑内容（包括未保存的修改），请自行保管。
- 导入 JSON 后先核对，再点击保存。导入替换资料后，原来的网页对应关系会失效。导出资料不包含网页对应关系。
- 卸载插件会清除浏览器中的插件资料。更换浏览器或卸载前请导出备份。本地存储不是加密保险箱。
- 插件仅申请 `storage`、`activeTab` 和 `scripting` 三项权限，在你点击插件后按需操作当前页面。权限机制参见 [activeTab 官方文档](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab) 与 [本地存储官方文档](https://developer.chrome.com/docs/extensions/reference/api/storage#storage_areas)。

## 当前范围

通用版支持有明确标签的标准 input、textarea、select、命名的原生 radio 组、普通 contenteditable、可访问的同源 iframe 和开放 Shadow DOM。用原生值设置及 input / change 事件通知网页，并检查网页是否接受内容。

通用版无法保证覆盖全部招聘网站。自定义级联地区、关闭的 Shadow DOM、跨域 iframe、特殊日期／富文本组件、附件上传、验证码和确认协议需要手动操作或针对具体网站适配。框架控件是否真正保存选项，仍需在网页上核对。当前未针对真实招聘网站逐站验证。

如果提示无法访问页面，请确认当前是普通招聘网页，并重新点一次插件。浏览器设置页、扩展商店、内置 PDF 阅读器和部分受限网页无法注入。网站刷新、弹层切换或表单结构变化后，请重新扫描；识别不到时使用手动指定。

## 源码与验证（开发者）

这是无构建依赖的 Manifest V3 插件。源码均在当前目录：

- `shared/profile.js`：资料分类、字段与导入校验。
- `shared/matcher.js`：中英文别名、保守匹配、选项与日期转换。
- `content.js`：扫描、经历分组、填入、撤销、手动映射。
- `options.*`：资料编辑与导入导出。
- `popup.*`：当前页预览与操作。
- `shared/applications.js`：投递记录校验、去重标识、网址清理与 CSV 编码。
- `recorder.js`：岗位识别、提交按钮检查、新结果提示观察。
- `tracker.*`：投递簿、跟进、编辑、筛选与导出导入。
- `background.js`：首次安装打开资料页、串行写入记录、跟踪会话与同源导航续接。

`npm test` 执行匹配器、记录校验、并发写入、请求隔离、去重和状态转换测试。安装 Playwright 后，运行 `npm run test:browser`、`npm run test:extension` 和 `npm run test:tracker` 可执行浏览器测试；可通过 `RESUMEKIT_BROWSER` 指定 Chromium 系浏览器程序路径，通过 `RESUMEKIT_NODE_MODULES` 指定 Playwright 包目录。`python build_release.py` 生成只包含运行文件和演示的安装 ZIP。

浏览器测试使用独立的测试浏览器资料目录，不操作日常浏览器。实际 `activeTab` 需要用户点击工具栏；无界面测试另建仅获准访问本地测试服务的测试插件副本，生产插件不包含全站访问权限。测试产物在 `tests/.artifacts`，不放入发布 ZIP 包。
